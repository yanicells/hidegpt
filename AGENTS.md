# AGENTS.md — HideGPT

HideGPT is a personal macOS stealth client for the user's own AI subscriptions.
It looks like Google Docs (light, student-y) but behaves like a chatbot.
There is no custom agent, no custom model plumbing, no chat database —
every capability comes from a provider subprocess that shares the user's
existing logins, and the UI is a Docs costume over it.

## What it is

- **Electron app** (`src/main/index.ts`, `src/preload/index.ts`, `src/renderer/`).
  React 19 renderer, IPC snapshot model: the main process owns session state
  and pushes `Snapshot` objects to the window; the renderer dispatches
  `Command`s back (`src/shared/api.ts`). Window title = document title,
  app name is "Docs".
- **Home = Docs file list.** `src/renderer/src/home.tsx` renders a template
  strip ("Start a new document") plus recent documents grouped by project.
  A document = one provider thread/session. Search filters server-side.
- **Document = one thread.** `src/renderer/src/document.tsx` renders provider
  blocks as page content on a paper-on-gray canvas (`styles.css`, Arial
  11pt, `--paper-width: 816px`). The composer is the last paragraph
  (`textarea.composer`, Enter to send). User turns render as headings,
  agent turns as Markdown body (`markdown.tsx`, react-markdown + remark-gfm).
- **Stealth rule:** nothing on screen may read as AI. Model/effort/speed/mode live
  in toolbar chips styled like Docs controls, never as raw model ids.
  Usage meters, provider names, and connection banners do not belong in the
  page — surface them under Tools, if at all. Toolbar dropdowns are portaled
  popovers (never inline in the scroll row); the model list is searchable.
  Plan mode is not offered on either provider.

## Providers (both are just transports)

- **Codex** (`src/codex/`): spawns `codex app-server`, JSON-RPC over stdio
  with **no `jsonrpc` field on the wire** (`jsonrpc.ts`, `transport.ts`).
  Handshake is `initialize` with `clientInfo.name: hidegpt` +
  `capabilities.experimentalApi: true`, then `initialized`. Shares `~/.codex`
  with the Codex CLI and ChatGPT desktop app — threads, projects, models,
  MCP servers (Notion etc.) come from there. Cloud ChatGPT Chat / Cloud Work
  are out of scope (no documented API). `src/generated/codex/` types are
  generated by `bun run protocol` (`codex app-server generate-ts
  --experimental`) — never hand-edit them, never invent protocol methods.
- **OpenCode** (`src/opencode/`): spawns `opencode serve` on 127.0.0.1 and
  talks REST + SSE (`GET /global/health`, `GET/POST /session`,
  `GET/POST /session/{id}/message`, `POST /session/{id}/abort`,
  `GET /event`). Same login reuse idea: it uses the user's existing
  `opencode auth` credentials. Maps onto the same `Snapshot`/`Block`
  shapes so the renderer barely knows which provider is active.

## State model

- `Snapshot` (`src/codex/types.ts`) is the single shared view-model:
  `provider`, `route` (home | doc), `title`, `blocks`, `streaming`,
  `threads`, `projects`, `models`/`model` (+ effort/mode for Codex),
  `account`, `search`, banners/error fields.
- `Block` (`src/codex/blocks.ts`) is the single content model:
  `user` | `agent` | `callout` (collapsed tool/diff activity) | `approval`
  (inline Accept/Skip cards). **Reasoning is never rendered** — filter it
  at the mapping layer, not in the UI.
- Sessions are authoritative for state; the renderer only renders.
  Optimistic user echoes must reconcile with the server-echoed item
  (same text, server id wins) so a sent message never appears twice.

## Docs-fidelity rules

- Page text is Arial 11pt (`--font-page`), UI chrome is the system Docs
  stack (`--font-ui`). User questions and agent answers share the body
  scale — a question is a section with a separator, not a giant heading.
- Turns are separated like document sections; an outline rail lists the
  questions and jumps to them (mirrors Docs' "Document tabs" / headings
  panel in the reference screenshots).
- Match `screenshots/` references (real Google Docs home grid, home list
  grouped by recency, editor with tabs panel + formatting toolbar) before
  inventing new chrome. List view groups loose docs by recency
  (Today / Yesterday / Previous 7 days / Previous 30 days) plus project
  sections, like Docs.

## Commands

```bash
bun install
bun run dev          # Electron app with Vite HMR
bun run test         # vitest: session/protocol + renderer UI tests
bun run typecheck    # tsc --noEmit
bun run protocol     # regenerate src/generated/codex from installed CLI
bun run screenshot   # PNGs of home + document with a fake session
```

`HIDEGPT_FAKE=1` runs the app against `src/codex/fake.ts` instead of a
real provider — use it for UI work and screenshots.

## Working agreements

- Small commits on a numbered branch, PR to `main`, no force-pushes.
- Renderer tests use `data-testid` hooks (`app`, `new-doc`, `home-search`,
  `thread-<id>`, `composer`, `menu-file`, …) — keep them working.
- Surgical edits: no new abstractions, no ChatGPT.com scraping, no
  protocol guessing. If a method isn't in the generated types (Codex) or
  the served OpenAPI (`/doc`, OpenCode), it doesn't exist.
- After changes: `bun run test && bun run typecheck`, plus `bun run
  screenshot` for UI changes.
